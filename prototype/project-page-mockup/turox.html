Why it exists

turox is a place to do performance work where the result can be measured, not argued. A chess engine is a clean target: move generation has an exact answer to check against, search speed is a number, and playing strength can be settled with a statistical test instead of a hunch. Every change either earns its place or gets reverted.

It is also a long-running Rust project with a real opponent pool. Playing as a bot on Lichess means it meets thousands of human and engine opponents it was never tuned against, which keeps the measured gains honest.

How it works

The board is a set of 64-bit bitboards, one per piece type and colour. Sliding-piece attacks come from precomputed magic tables, so generating moves is mostly lookups and bit operations. Search is iterative-deepening alpha-beta with a transposition table, and the evaluation is hand-written and tuned against self-play.

Key decisions

  • Magic bitboards over a mailbox board. Lookups beat loops for sliding pieces, at the cost of a startup table build. See ADR 0002.
  • SPRT as the only gate on strength. Self-play matches stop as soon as the result is statistically clear, so small gains are cheap to test. See ADR 0004.
  • Hand-written evaluation, not NNUE. Every term stays explainable while the search is still the bottleneck.
